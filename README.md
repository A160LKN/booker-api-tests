# Booker API Tests

[![API tests](https://github.com/A160LKN/booker-api-tests/actions/workflows/tests.yml/badge.svg?branch=main)](https://github.com/A160LKN/booker-api-tests/actions/workflows/tests.yml)

Автотесты REST API учебного сервиса бронирования отелей [Restful Booker](https://restful-booker.herokuapp.com/apidoc/index.html).

**Allure-отчёт последнего прогона:** https://a160lkn.github.io/booker-api-tests/

## Стек

- Python 3.10+
- requests
- pytest
- Pydantic — модели данных и проверка контракта
- Allure Report
- Postman и Newman

## Что проверяется — 18 API-тестов и 23 проверки моделей

**Доступность и авторизация**
- сервис отвечает на `/ping`;
- с верными данными выдаётся токен, с неверными — нет.

**Бронирования (CRUD)**
- создание, получение по id, поиск по имени и фамилии;
- полное обновление (`PUT`) и частичное (`PATCH`) с проверкой, что изменения сохранились;
- удаление и проверка, что бронирование больше не находится;
- `404` для несуществующего бронирования.

**Безопасность**
- без токена и с поддельным токеном нельзя изменить или удалить бронирование — и данные при этом не меняются.

**Валидация**
- создание без обязательных полей (параметризованный тест).

**Модели данных** — без сети, за доли секунды (`pytest -m unit`)
- модель отклоняет неверные ответы: число строкой, дробную или отрицательную цену, пустое имя, лишнее поле, несуществующую дату, выезд раньше заезда, токен вместе с ошибкой авторизации.

## Контракт API на Pydantic

Каждый ответ проверяется моделью, а не набором отдельных `assert`:

```python
created = CreatedBooking.model_validate(response.json())
assert created.booking == booking
```

Одна модель `Booking` служит и телом запроса, и проверкой ответа. Модели строгие:
- `"150"` вместо `150` — ошибка, а не тихое приведение типа;
- **лишнее поле в ответе — ошибка**: если API начнёт возвращать что-то новое, тест об этом скажет;
- даты проверяются как настоящие даты, а не по маске: `2027-02-30` не пройдёт; выезд не может быть раньше заезда.

Сами модели тоже покрыты тестами — модель, которая пропускает неверный ответ, хуже, чем никакой.

## Коллекция Postman

[`postman/booker.postman_collection.json`](postman/booker.postman_collection.json) — те же сценарии для ручной проверки и демонстрации: 13 запросов, 35 проверок.

- запросы связаны переменными: токен из авторизации и id созданного бронирования подставляются дальше;
- у каждого запроса — тесты на `pm.test`, у создания — проверка ответа по JSON-схеме;
- в CI коллекция запускается через **Newman** отдельной задачей.

Импорт: Postman → Import → выбрать файл → Run collection.

## Найденные особенности и баги API

| Что | Ожидалось | Фактически |
| --- | --- | --- |
| Неверный пароль в `POST /auth` | `401 Unauthorized` | `200 OK` с `{"reason": "Bad credentials"}` |
| Успешный `DELETE /booking/{id}` | `200 OK` или `204 No Content` | `201 Created` |
| `POST /booking` без обязательного поля | `400 Bad Request` | `500 Internal Server Error` |

Тесты на последний баг помечены `xfail`: прогон остаётся зелёным, а в отчёте видно, что дефект известен. Когда баг исправят, тест покажет `XPASS`.

## Особенности проекта

- **API-клиент** `BookerClient` — один метод на эндпоинт, тесты не знают об URL и заголовках;
- **проверка контракта** моделями Pydantic;
- **фикстуры с уборкой**: каждое бронирование, созданное тестом, удаляется после него;
- **уникальные тестовые данные**: API общий для всех, поэтому имя в каждом бронировании уникальное;
- токен запрашивается **один раз** на весь прогон (`scope="session"`);
- каждый запрос и ответ **прикрепляется к Allure-отчёту**;
- **CI на GitHub Actions**: pytest и коллекция Postman при каждом изменении и раз в день по расписанию. Стенд чужой и бесплатный, поэтому в CI тест, упавший из-за сети или ответа 5xx от стенда, повторяется до двух раз; падение из-за логики не повторяется.

## Структура

```

├── postman
```

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

pytest            # все тесты
pytest -m unit    # только модели — без сети

# Коллекция Postman из командной строки
npx newman run postman/booker.postman_collection.json

# Allure-отчёт
allure serve allure-results
```
